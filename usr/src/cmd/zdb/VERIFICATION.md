# Original-BP raw checksum diagnostic (review hold)

New opt-in `-Y OUTPUT -e -p /absolute/device-directory POOL` adds synchronous raw reads to the paired `-K` exporter. Do not run this bundle in a lab until independent review clears it. No builder pool reads, deployment, relocation, or pushes are part of this implementation.

Each eligible BP reference retains all 128 normalized BP bytes and its original bookmark. The diagnostic allocates an ABD of P=BP_GET_PSIZE, submits zio_read with CANFAIL|SCRUB|RAW and SYNC_READ, and calls zio_wait before returning from the traversal callback. No speculative or error-suppression flags are used. Duplicate references are deliberately reread; verified byte totals count references, not unique extents.

Only ordinary unprotected nongang non-dedup BPs with valid supported RAID-Z geometry and Fletcher4 (7) or SHA256 (8) checksums qualify. DDT object types 42,43,49 are excluded. Holes and embedded BPs receive unmeasured not_applicable dispositions. All unsupported/read failures abort traversal; no successful result is inferred from skipped children. The existing traversal excludes ZIL and decrypting traversal, and is not a complete ownership proof.

P is the stored payload/checksum domain. Q is sector-rounded data for RAID-Z dispatch, and A includes parity/padding allocation. Q/A are never substituted for P at submission. RAW keeps compressed stored bytes; this does not validate decompression or plaintext. Protected blocks are excluded, so this is not MAC validation.

The completion callback checks the full original BP, bookmark, ABD identity, P-sized original/final sizes, read type, flags, and read-only mode. A measured success requires exactly one callback, agreement with zio_wait, zero error, and unchanged inputs. Each result immediately follows its BP. The terminal verifies submitted=completed=passed, zero outstanding/failed/unsupported, disposition counts and requested=verified P totals. Limits: 16 MiB per BP, 1 GiB total requested P, existing 300-second process and 1M traversal-record caps.

Read-only gates require spa_mode == FREAD and !spa_writeable before submission and after completion; main initializes kernel_init(FREAD). In the pinned vdev_raidz.c, repair writes are gated by spa_writeable. Native fixture instrumentation asserts zero attempted diagnostic zio_write calls and tests writable-mode refusal; its ZIO stubs do NOT exercise the real repair pipeline. Real fault-injection zero-write behavior remains a lab validation requirement. A successful logical read may recover using another DVA or RAID-Z reconstruction; it does not prove every replica or member healthy.

verified_intervals.py requires the exact stream SHA256, external successful process exit, final cut equality, drained terminal counters, and paired allocation consistency. It binds each result to its BP sequence, full BP and bookmark and rejects missing/duplicate/unsupported/failed results. Close failure can occur after an apparently complete JSON terminal, so the external exit status is mandatory. All global coverage_complete, payload_validation_performed, and evacuation_authorized flags remain false; per-record measured is the narrow evidence indicator.

Validation: native mocked ZIO success/duplicate/error/malformed completion/read-only/byte cap/output failure cases; pinned real Fletcher4 and SHA256 checksum corruption and P-versus-padding checks; analyzer binding/counter/cut/error cases; prior exporter and allocation regressions. Checksum fixture bytes labeled compressed are not a valid compression-stream test. Fixture setup required explicit fletcher_4_init/fini and abd_put for borrowed-buffer ABDs; no pool initialization was used.

Independent review should examine callback semantics, read-only repair guards, full BP identity, raw P domain, unsupported disposition behavior, terminal/output binding and retained false global claims. Only after clearance should the coordinator run the disposable exported-pool fixture and controlled single-DVA missing-member case, distinguishing alternate-copy recovery from reconstruction.
